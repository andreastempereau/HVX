ARCHITECTURE CHANGE:
  FROM: Microservices with gRPC inter-process communication
         - Video Service (50051)
         - Perception Service (50052)
         - Voice Service (50053)
         - Orchestrator Service (50054)
         
  TO:   Monolithic Qt/QML application with direct hardware access
         - All functions in single process (visor-ui)
         - Direct camera, IMU, GPS, voice processing
         - Simpler deployment, lower latency

================================================================================
                              IMPACT ANALYSIS
================================================================================

PROS:
  ✓ Reduced codebase by 32% (2934 lines)
  ✓ Simpler deployment (single process vs 5 services)
  ✓ Lower latency (no IPC overhead)
  ✓ Easier debugging (single stack trace)
  ✓ Reduced memory footprint
  ✓ Fewer Docker images to maintain
  ✓ Unified error handling

CONS:
  ✗ Must refactor UI to call hardware directly
  ✗ Loss of service isolation (but single-app anyway)
  ✗ Potential for larger binary
  ✗ Requires testing of refactored code

RISK LEVEL: LOW
  - UI already has direct hardware handlers
  - Service clients are thin wrappers (simple to replace)
  - No loss of functionality
  - All hardware drivers remain the same
